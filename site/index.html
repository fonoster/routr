Scale

Stateful at the edge.
Stateless everywhere else.

Only EdgePorts hold state. The Location Service knows which EdgePort each endpoint is on, so a call can land on any of them and still arrive.

1001caller edgeport-01holds 1001's connection dispatcherstateless connectstateless edgeport-02holds 1002's connection 1002callee
00.0001001 → edgeport-01INVITE sip:1002@sip.local
00.002edgeport-01 → dispatcherSIP becomes protobuf; the EdgePort keeps the transaction
00.003dispatcher → connectstateless: match req => true, forward
00.005connectlocation lookup on redis: 1002 is registered on edgeport-02
00.006connectadds Route: edgeport-02 and X-EdgePort-Ref: edgeport-01
00.008edgeport-01 → edgeport-02hands the INVITE to the EdgePort that holds 1002
00.010edgeport-02 → 1002delivered on the existing connection

Across EdgePorts

Any EdgePort takes any call and hands it to the one that holds the target.

Across media servers

A Peer groups Asterisk or FreeSWITCH behind one address: round-robin, least-sessions, session affinity.

Across services

Stateless replicas behind a Kubernetes service. Location shared on Redis.

Resilience

No single point of failure.

Every service is its own pod. Lose an EdgePort, the others keep taking calls. Lose a Processor, the Dispatcher routes around it.

Calls keep flowing.

Programmable

Extend it in any language.

Processors and Middlewares are gRPC services. Write one in Node, Go, or Java and swap it in.
