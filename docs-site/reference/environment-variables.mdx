Routr 3 reads its settings from YAML files, secrets included. A Routr component reads one environment variable on its own, `CONFIG_PATH`, the path of its configuration file. Every other value comes from the file. See [routr.yaml](/reference/configuration) and [Standalone component files](/reference/configuration-files).

An environment variable still reaches a setting when the file names it. Write it as a placeholder or as a reference:

```yaml
spec:
  data:
    url: ${DATABASE_URL}                 # or secret://env/DATABASE_URL
telemetry:
  otlpEndpoint: ${OTEL_EXPORTER_OTLP_ENDPOINT:-}
```

Setting a Routr 2 variable such as `NONCE_MAX_AGE` on a Routr 3 container does nothing, and nothing warns you. Move each one into the file before you upgrade. The tables below map every variable to its key.

## What Routr 3 still reads

| Variable | Read by | Purpose |
| --- | --- | --- |
| `CONFIG_PATH` | Every component | Path of the configuration file. Each image sets it; see [Standalone component files](/reference/configuration-files) |
| `ROUTR_SECRETS_DIR` | Every component, for `secret://k8s` | Where Kubernetes Secrets are mounted. Default `/var/run/routr/secrets` |
| `POD_NAMESPACE` | Every component, for `secret://k8s` | When set, a reference that names a namespace must name this one |
| Any variable the file names | Every component | Through `${VAR}`, `${VAR:-default}` or `secret://env/VAR` |
| `PKCS12_PASSWORD`, `PATH_TO_CERTS`, `CA_CERT_SUBJECT`, `SERVER_CERT_SUBJECT` | The startup script of the `routr-one` and `routr-edgeport` images | Generate a self-signed certificate when none is mounted and build `signaling.p12`. Routr itself doesn't read them: `keyStorePassword` must hold the same password |

### The standalone EdgePort

The `fonoster/routr-edgeport` image still reads Routr 2's EdgePort variables, so a Routr 2 deployment keeps working. Where a variable and `edgeport.yaml` name the same setting, the variable wins, as it did in Routr 2. RoutrOne doesn't read any of them.

| Variable | Effect | In `edgeport.yaml` |
| --- | --- | --- |
| `EXTERNAL_ADDRS` | Comma-separated public addresses | `spec.externalAddrs` |
| `LOCALNETS` | Comma-separated local CIDRs | `spec.localnets` |
| `ALIASES` | Comma-separated aliases | `spec.aliases` |
| `PROCESSOR_ADDR` | Address of the Dispatcher | `spec.processor.addr` |
| `HOSTNAME` | Replaces `ref` | `ref` |
| `LOGS_LEVEL` | Replaces `logLevel` | `logLevel` |
| `SECURITY_CONTEXT_CLIENT_PROTOCOLS` | TLS versions | `spec.securityContext.client.protocols` |
| `SECURITY_CONTEXT_CLIENT_CIPHER_SUITES` | TLS 1.2 cipher suites | `spec.securityContext.client.cipherSuites` |
| `IGNORE_LOOPBACK_FROM_LOCALNETS` | `true` leaves loopback out of the localnets read from the host | No key |
| `STRIP_SESSION_PROGRESS_SDP` | `true` removes the body of `183 Session Progress` | No key |
| `ENABLE_HEALTHCHECKS` | `true` serves `GET /healthz` on port `8080` | No key |
| `CONSOLE_PUBLISHER_ENABLED` | `true` prints call events | No key |
| `NATS_PUBLISHER_ENABLED`, `NATS_PUBLISHER_URL`, `NATS_PUBLISHER_SUBJECT` | Publish call events to NATS. Defaults `nats://localhost:4222` and `routr` | No key |
| `JAIN_SIP_TRACE_LEVEL` | Any value turns on the SIP stack's own log | No key |

The settings marked "No key" exist only in the standalone EdgePort. RoutrOne 3 has no way to turn them on.

## Routr 2 variables and their keys

A key written `spec.x` in the RoutrOne column is in `routr.yaml`. The standalone column names the file and key a separate image reads.

### Container and database

| Routr 2 variable | RoutrOne 3 | Standalone |
| --- | --- | --- |
| `DATABASE_URL` | `spec.data.url`, for example `secret://env/DATABASE_URL`. The URL works as it is, `?schema=public` included | `data.yaml`: `spec.data.url` |
| `START_INTERNAL_DB` | Removed. RoutrOne 3 has no internal database: use `backend: files` or an external PostgreSQL | |
| `ROUTR_ONE_CONFIG` | `CONFIG_PATH`. The file is `routr.yaml`, not `one.yaml` | |
| `HEPLIFY_OPTIONS` | Removed. The images don't ship heplify | |
| `EDGEPORT_RUNNER`, `JAVA_HOME`, `LOG4J2` | Removed with the Java EdgePort | |

### EdgePort

| Routr 2 variable | RoutrOne 3 | Standalone |
| --- | --- | --- |
| `EXTERNAL_ADDRS` | `spec.edgeport.externalAddrs` | Still read; or `spec.externalAddrs` |
| `LOCALNETS` | `spec.edgeport.localnets` | Still read; or `spec.localnets` |
| `ALIASES` | `spec.edgeport.aliases` | Still read; or `spec.aliases` |
| `HOSTNAME` | `ref` | Still read |
| `PROCESSOR_ADDR` | Not needed | Still read; or `spec.processor.addr` |
| `PKCS12_PASSWORD` | Still read by the image's script; set `spec.edgeport.securityContext.keyStorePassword` to the same value | Same |
| `SECURITY_CONTEXT_CLIENT_PROTOCOLS` | `spec.edgeport.securityContext.client.protocols` | Still read |
| `SECURITY_CONTEXT_CLIENT_CIPHER_SUITES` | `spec.edgeport.securityContext.client.cipherSuites` | Still read |
| `ENABLE_HEALTHCHECKS` | `spec.health` | Still read |
| `IGNORE_LOOPBACK_FROM_LOCALNETS`, `STRIP_SESSION_PROGRESS_SDP`, `CONSOLE_PUBLISHER_ENABLED`, `NATS_PUBLISHER_*`, `JAIN_SIP_TRACE_LEVEL` | No key | Still read |

### Requester and Registry

| Routr 2 variable | RoutrOne 3 | Standalone |
| --- | --- | --- |

### Logs and telemetry

| Routr 2 variable | Routr 3 |
| --- | --- |
| `LOGS_LEVEL` | `logLevel`: `debug`, `info`, `warn` or `error` |
| `LOGS_FORMAT`, `LOGS_TRANSPORT`, `LOGS_DRIVER_HOST`, `LOGS_DRIVER_PORT`, `LOGS_OPT_TAG_PREFIX` | Removed. Logs go to standard output, and to OTLP when telemetry is on |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | `telemetry.otlpEndpoint`. Write `${OTEL_EXPORTER_OTLP_ENDPOINT:-}` to keep reading the variable |
| `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` | Removed. One base URL serves all three signals |
| `OTEL_SDK_DISABLED` | Leave `telemetry.otlpEndpoint` absent or empty |
| `OTEL_SERVICE_NAME` | Removed. Each binary reports its own name, such as `routr-one` or `connect` |
| `OTEL_TRACES_SAMPLER`, `OTEL_TRACES_SAMPLER_ARG` | `telemetry.sampleRatio` |

### Clients

`rctl` and the SDK are Node programs and keep reading their variables. `rctl` takes `ROUTR_API_KEY` for `--api-key`; both take `ALLOW_INSECURE=true` to reach a Data API without TLS. See [rctl](/reference/rctl) and the [SDK](/reference/sdk).

## Ports

| Port | Protocol | Component | Set by |
| --- | --- | --- | --- |
| `5060` | SIP over UDP and TCP | EdgePort | `spec.edgeport.transport` |
| `5061` | SIP over TLS | EdgePort | `spec.edgeport.transport` |
| `5062` | SIP over WS | EdgePort | `spec.edgeport.transport` |
| `5063` | SIP over WSS | EdgePort | `spec.edgeport.transport` |
| `51901` | gRPC | Message Dispatcher | `spec.dispatcher.bindAddr` |
| `51902` | gRPC | Location | `spec.location.bindAddr` |
| `51903` | gRPC | RTPRelay, standalone only | `rtprelay.yaml`: `spec.bindAddr` |
| `51904` | gRPC | Connect | `spec.connect.bindAddr` |
| `51907` | gRPC | Data API, for `rctl` and the SDK | `spec.data.bindAddr` |
| `51909` | gRPC | Requester | `spec.requester.bindAddr` |
| `8080` | HTTP `/healthz` | RoutrOne with `spec.health`, the Registry | `spec.health.bindAddr` |

Routr 2's external API port, `51908`, is gone from the images. The Helm chart's Data API Service still offers it, routed to `51907`.
