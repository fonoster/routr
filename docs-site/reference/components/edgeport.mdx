title: "EdgePort"
description: "Reference for the EdgePort: its image, ports, configuration file, environment variables, and gRPC contract."
---

The EdgePort is the SIP entry point of Routr. It holds SIP connections and transactions, converts each SIP message to a protobuf `MessageRequest`, sends it to the Message Dispatcher (or straight to a Processor), and sends the resulting SIP message to the next hop. It is the only stateful Routr service, and it is written in Java.

## Docker image

`fonoster/routr-edgeport`

The image reads its configuration from `/etc/routr/edgeport.yaml` (`CONFIG_PATH`). On start, it converts the certificates in `/etc/routr/certs` to the PKCS12 keystore `signaling.p12`. If `server.crt` or `server.key` is missing, it generates self-signed certificates first.

## Ports

| Port | Protocol | Purpose |
| --- | --- | --- |
| Set by `spec.transport[*].port` | UDP, TCP, TLS, WS, WSS | SIP signaling. Common values: `5060` (UDP and TCP), `5061` (TLS), `5062` (WS), `5063` (WSS) |
| `8080` | HTTP | Health check at `/healthz`, only when `ENABLE_HEALTHCHECKS=true` |

## Configuration file

The EdgePort reads a YAML or JSON file and validates it against a JSON schema at startup.

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `kind` | string | Yes | | Resource type. Use `EdgePort` |
| `apiVersion` | string | Yes | | `v2beta1` or `v2` |
| `ref` | string | Yes | | EdgePort reference. `HOSTNAME` overrides it when set |
| `metadata.region` | string | No | | Region where the EdgePort operates (reserved for future use) |
| `spec.bindAddr` | string | No | `0.0.0.0` | IPv4 interface to accept requests on |
| `spec.externalAddrs` | string[] | No | `[]` | External addresses of the EdgePort (IPs or hostnames). `EXTERNAL_ADDRS` overrides it |
| `spec.localnets` | string[] | No | Networks reported by the OS | Networks considered local, in CIDR form. `LOCALNETS` overrides it |
| `spec.methods` | string[] | Yes | | Acceptable SIP methods |
| `spec.unknownMethodAction` | string | No | | `Discard` or `Respond` (reserved for future use) |
| `spec.transport` | object[] | Yes | | Listening points. One entry per protocol |
| `spec.transport[*].protocol` | string | Yes | | `udp`, `tcp`, `tls`, `ws`, or `wss` |
| `spec.transport[*].port` | integer | Yes | | Port to listen on. Only `udp` and `tcp` can share a port |
| `spec.transport[*].bindAddr` | string | No | `spec.bindAddr` | IPv4 interface for this transport |
| `spec.processor.addr` | string | Yes | | Address of the Dispatcher or Processor, for example `dispatcher:51901`. `PROCESSOR_ADDR` overrides it |
| `spec.securityContext` | object | Yes, for `tls` or `wss` | | TLS settings for the SIP stack |
| `spec.securityContext.client.protocols` | string[] | No | `[TLSv1.3]` | TLS versions for the TLS and WSS transports, incoming and outgoing, for example `TLSv1.3`, `TLSv1.2`. `SECURITY_CONTEXT_CLIENT_PROTOCOLS` overrides it |
| `spec.securityContext.client.cipherSuites` | string[] | No | See below | Cipher suites for the TLS and WSS transports, using JDK names. `SECURITY_CONTEXT_CLIENT_CIPHER_SUITES` overrides it |
| `spec.securityContext.client.authType` | string | No | | Client authentication type: `Disabled`, `DisabledAll`, `Required`, or `Wanted`. Use `Disabled` or `DisabledAll` with WSS |
| `spec.securityContext.keyStore` | string | No | | Path to the keystore, for example `/etc/routr/certs/signaling.p12` |
| `spec.securityContext.trustStore` | string | No | JVM truststore | Path to a truststore with the CAs the EdgePort trusts on connections it opens, for example to a carrier over TLS. Leave it unset to trust the public CAs in the JVM's `cacerts`. Don't point it at `signaling.p12`: that trusts only the EdgePort's own certificate and fails the handshake to a carrier |
| `spec.securityContext.keyStorePassword` | string | No | | Keystore password |
| `spec.securityContext.trustStorePassword` | string | No | | Truststore password. Only with `trustStore` |
| `spec.securityContext.keyStoreType` | string | No | | Keystore type, for example `pkcs12` |

The `securityContext` fields map to the JAIN SIP `javax.net.ssl.*`, `gov.nist.javax.sip.TLS_CLIENT_*`, and `gov.nist.javax.sip.ENABLED_CIPHER_SUITES` properties.

When `cipherSuites` is unset, the EdgePort enables these suites. The TLS 1.2 suites only take effect when `protocols` includes `TLSv1.2`.

| Version | Cipher suites |
| --- | --- |
| TLS 1.3 | `TLS_AES_256_GCM_SHA384`, `TLS_AES_128_GCM_SHA256`, `TLS_CHACHA20_POLY1305_SHA256` |
| TLS 1.2 | `TLS_ECDHE_ECDSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384`, `TLS_ECDHE_ECDSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_RSA_WITH_AES_128_GCM_SHA256`, `TLS_ECDHE_ECDSA_WITH_CHACHA20_POLY1305_SHA256`, `TLS_ECDHE_RSA_WITH_CHACHA20_POLY1305_SHA256` |

Use the names the Java runtime knows. A name it doesn't recognize makes every TLS and WSS connection fail. The runtime in the Routr images also disables RSA key exchange, 3DES, and anonymous suites, so listing them has no effect.

| `NATS_PUBLISHER_SUBJECT` | `routr` | NATS subject for events |

## Telemetry

With `OTEL_EXPORTER_OTLP_ENDPOINT` set, the EdgePort sends over OTLP:

- **Traces:** one `SIP <METHOD>` span per request it receives, from arrival to its final response.
  It carries `sip.method`, `sip.call_id`, `network.transport`, `network.peer.address`,
  `network.peer.port` and `sip.status_code`. A request that never gets a final response ends as an
  error when its transaction times out.
- **Metrics:** `routr.sip.requests` (by method and transport), `routr.sip.responses` (by method
  and status), `routr.sip.timeouts`, `routr.sip.transport_errors`, and `routr.sip.send_dropped`
  (by `routr.drop.reason`, transport and method): messages the EdgePort dropped instead of
  sending. Sent every 15 seconds.
- **Logs:** every Log4j2 record of the `io.routr` loggers. A dropped message's record names its
  first line and Call-ID.

## gRPC contract

The EdgePort is a gRPC client. For every SIP request and response, it calls `ProcessMessage` on the address in `spec.processor.addr`.

| Service | Method | Request | Response |
| --- | --- | --- | --- |
| `fonoster.routr.processor.v2beta1.Processor` | `ProcessMessage` | `MessageRequest` | `MessageResponse` |

`MessageRequest` carries the Call-ID (`ref`), the EdgePort reference (`edge_port_ref`), the SIP method, the sender, the listening points, `external_addrs`, `localnets`, the SIP message, and metadata. See [processor.proto](https://github.com/fonoster/routr/blob/main/mods/common/src/protos/processor.proto) and [sipmessage.proto](https://github.com/fonoster/routr/blob/main/mods/common/src/protos/sipmessage.proto).

## Minimal example

This configuration accepts SIP over UDP and TCP and sends messages to the Dispatcher.

```yaml
kind: EdgePort
apiVersion: v2beta1
ref: edgeport-01
spec:
  externalAddrs:
    - 192.168.1.3
  methods:
    - REGISTER
    - MESSAGE
    - INVITE
    - ACK
    - BYE
    - CANCEL
  transport:
    - protocol: udp
      port: 5060
    - protocol: tcp
      port: 5060
  processor:
    addr: dispatcher:51901
```

This command runs the EdgePort with that file.

```bash
docker run -it \
  -v $(pwd)/edgeport.yaml:/etc/routr/edgeport.yaml \
  -p 5060:5060/udp -p 5060:5060 \
  fonoster/routr-edgeport
```

## Notes

- Behind NAT (Docker, Kubernetes, cloud VMs), set `spec.externalAddrs` or `EXTERNAL_ADDRS`. Processors use these addresses to build the advertised address.
- Publish every port in `spec.transport` from the container.
- A `tls` or `wss` transport without `spec.securityContext` stops the EdgePort at startup.
- Because `HOSTNAME` overrides `ref`, the EdgePort reference in Docker and Kubernetes is the container or pod hostname.
- With several EdgePorts, configure the Connect processor to trust its peer EdgePorts. See [Connect processor](/reference/components/connect).
