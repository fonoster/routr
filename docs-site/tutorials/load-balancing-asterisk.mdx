## What you'll build

You run Routr and two Asterisk containers with Docker Compose. Both Asterisk servers register to Routr with the same credentials, so Routr groups them under one Peer and one Address of Record (AOR). When a softphone calls the Peer, the Location Service picks one of the registered Asterisk servers for each new call.

<Info>
Routr balances **new** calls. It picks a server when a call starts, and the call stays on that server until it ends. Routr does not move in-flight calls, and it does not recover a call if the Asterisk server handling it goes away.
</Info>

## Prerequisites

- Docker with Docker Compose
- Node.js 22 or later, to install `rctl`
- A SIP softphone such as Zoiper or Linphone
- The IP address of your machine on your local network (for example, `192.168.1.3`)

## Steps

<Steps>
  <Step title="Create the project files">
    Create a folder for the tutorial and move into it.

    ```bash
    mkdir routr-asterisk && cd routr-asterisk
    ```

    Download the English core sounds. The Asterisk image doesn't include prompts, and the dialplan below needs them to say a digit.

    ```bash
    mkdir sounds
    curl -sL https://downloads.asterisk.org/pub/telephony/sounds/releases/asterisk-core-sounds-en-ulaw-1.6.1.tar.gz | tar -xz -C sounds
    ```

    Create the PJSIP configuration both Asterisk servers share. It registers to Routr as the `asterisk` Peer and accepts the calls Routr sends back.

    Filename: `pjsip.conf`

    ```ini
    [transport-udp]
    type=transport
    protocol=udp
    bind=0.0.0.0:5060

    [routr]
    type=registration
    transport=transport-udp
    server_uri=sip:routr:5060
    client_uri=sip:asterisk@sip.local
    outbound_auth=routr-auth
    expiration=60
    retry_interval=10
    forbidden_retry_interval=10

    [routr-auth]
    type=auth
    auth_type=userpass
    username=asterisk
    password=asterisk

    [routr]
    type=endpoint
    transport=transport-udp
    context=local-ctx
    disallow=all
    allow=ulaw,alaw

    [routr]
    type=identify
    endpoint=routr
    match=routr
    ```

    What each section does:

    - `registration` sends a REGISTER to the `routr` service every minute. The user part of `client_uri` is the Peer's username, which is how Routr finds the Peer. `forbidden_retry_interval` keeps it retrying after a `403 Forbidden`, which is what Routr answers until the Peer exists.
    - `auth` holds the Peer's credentials. Asterisk uses them to answer Routr's `401` challenge.
    - `endpoint` and `identify` accept calls that come from the `routr` service and send them to the `local-ctx` context. Routr doesn't challenge the calls it forwards, so the endpoint has no inbound authentication.

    Create a dialplan for each Asterisk server. Each one answers calls to the `asterisk` extension, logs its own name, and says a different digit, so you can tell them apart.

    Filename: `extensions.01.conf`

    ```ini
    [local-ctx]
    exten => asterisk,1,NoOp()
     same => n,Verbose(1, Call answered by asterisk01)
     same => n,Answer()
     same => n,SayDigits(1)
     same => n,Hangup()
    ```

    Filename: `extensions.02.conf`

    ```ini
    [local-ctx]
    exten => asterisk,1,NoOp()
     same => n,Verbose(1, Call answered by asterisk02)
     same => n,Answer()
     same => n,SayDigits(2)
     same => n,Hangup()
    ```
  </Step>

  <Step title="Define the services">
    Create a `compose.yaml` file. It runs `routr-one` (all Routr components plus an internal database), two Asterisk servers, and RTPEngine for media.

    Filename: `compose.yaml`

    ```yaml
    services:
      routr:
        image: fonoster/routr-one:latest
        environment:
          EXTERNAL_ADDRS: ${DOCKER_HOST_ADDRESS}
          RTPENGINE_HOST: rtpengine
        ports:
          - 51908:51908
          - 5060:5060
          - 5060:5060/udp

      asterisk01:
        image: andrius/asterisk:22.11.0_debian-trixie
        restart: always
        volumes:
          - ./pjsip.conf:/etc/asterisk/pjsip.conf:ro
          - ./extensions.01.conf:/etc/asterisk/extensions.conf:ro
          - ./sounds:/var/lib/asterisk/sounds/en:ro

      asterisk02:
        image: andrius/asterisk:22.11.0_debian-trixie
        restart: always
        volumes:
          - ./pjsip.conf:/etc/asterisk/pjsip.conf:ro
          - ./extensions.02.conf:/etc/asterisk/extensions.conf:ro
          - ./sounds:/var/lib/asterisk/sounds/en:ro

      rtpengine:
        image: fonoster/rtpengine:latest
        platform: linux/amd64
        ports:
          - 22222:22222/udp
          - 10000-10100:10000-10100/udp
        environment:
          RTPENGINE_PUBLIC_IP: ${DOCKER_HOST_ADDRESS}
          RTPENGINE_PORT_MIN: 10000
          RTPENGINE_PORT_MAX: 10100
    ```

    Both Asterisk services mount the same `pjsip.conf`, so they register with the same username and password. That is what makes Routr treat them as one Peer. Only the dialplan differs.

    <Note>
    `andrius/asterisk` is a community-maintained build of stock Asterisk, published for amd64 and arm64. The tag pins Asterisk 22, a long-term support release. The configuration is plain PJSIP, so it works with any Asterisk build that includes PJSIP. `fonoster/rtpengine` is built for amd64 only, so on Apple silicon it runs under emulation.
    </Note>
  </Step>

  <Step title="Start the stack">
    Start the services. Replace the address with your own.

    ```bash
    DOCKER_HOST_ADDRESS=192.168.1.3 docker compose up -d
    ```

    Check that the containers are up.

    ```bash
    docker compose ps
    ```

    You see four services with status `Up` (or `running`). The Asterisk servers try to register right away and Routr rejects them, because the Peer doesn't exist yet. You create it next. They keep retrying every 10 seconds.

    Asterisk logs warnings and errors at startup from modules this tutorial doesn't use, such as ALSA, PostgreSQL, and CDR. You can ignore them.
  </Step>

  <Step title="Install rctl">
    Install the command-line tool.

    ```bash
    npm install --location=global @routr/ctl
    ```

    The `--insecure` flag in the next steps is required because this setup doesn't use TLS on the API.
  </Step>

  <Step title="Create a Domain and an Agent">
    Create the Domain your softphone registers to.

    ```bash
    rctl domains create --insecure
    ```

    Answer the prompts like this:

    ```text
    This utility will help you create a new Domain.
    Press ^C at any time to quit.
    ? Friendly Name Local Domain
    ? SIP URI sip.local
    ? IP Access Control List None
    ? Add an Egress Rule? No
    ? Ready? Yes
    Creating Domain Local Domain... a27e9fb2-a71a-4cf3-9b1d-dccf373f9777
    ```

    Create credentials for the Agent, using `1001` as the username and `1234` as the password.

    ```bash
    rctl credentials create --insecure
    ```

    Then create the Agent and link it to the Domain and credentials.

    ```bash
    rctl agents create --insecure
    ```

    ```text
    This utility will help you create a new Agent.
    Press ^C at any time to quit.
    ? Friendly Name John Doe
    ? Select a Domain sip.local
    ? Username 1001
    ? Credentials Name John Doe Credentials
    ? Max Contacts
    ? Privacy None
    ? Enabled? Yes
    ? Ready? Yes
    Creating Agent John Doe... 8dae9a7d-99b8-4279-88e1-4cf6ed67190a
    ```
  </Step>

  <Step title="Create the Asterisk Peer">
    Create the credentials both Asterisk servers share: username `asterisk`, password `asterisk`.

    ```bash
    rctl credentials create --insecure
    ```

    ```text
    This utility will help you create a new set of Credentials.
    Press ^C at any time to quit.
    ? Friendly Name Asterisk Credentials
    ? Username asterisk
    ? Password [hidden]
    ? Ready? Yes
    Creating Credentials Asterisk Credentials... 7364eddf-0756-4cb5-8b35-1a90681589ca
    ```

    Create the Peer. Use `asterisk` as the username and `sip:asterisk@sip.local` as the AOR. Leave **Contact Address** and **Max Contacts** empty, so any number of servers can register under the AOR. Choose **Round Robin**.

    ```bash
    rctl peers create --insecure
    ```

    ```text
    This utility will help you create a new Peer.
    Press ^C at any time to quit.
    ? Friendly Name Asterisk PBX
    ? Username asterisk
    ? Address of Record sip:asterisk@sip.local
    ? Contact Address
    ? Max Contacts
    ? IP Access Control List None
    ? Credentials Name Asterisk Credentials
    ? Enable Session Affinity? No
    ? Balancing Algorithm Round Robin
    ? Enabled? Yes
    ? Ready? Yes
    Creating Peer Asterisk PBX... 7ae0ddcf-e13d-4456-99f0-0bc4ef68a05d
    ```

    List the Peers to confirm.

    ```bash
    rctl peers get --insecure
    ```

    ```text
    Name           Username   AOR                      Max Contacts   Balancing Algorithm   Enabled
    Asterisk PBX   asterisk   sip:asterisk@sip.local                  Round Robin           Yes
    ```
  </Step>

  <Step title="Check that the Asterisk servers registered">
    Within 10 seconds of creating the Peer, both servers retry and register. Each one registers from its own container address, and Routr stores both contacts under `sip:asterisk@sip.local`.

    Ask each server for its registration status.

    ```bash
    docker compose exec asterisk01 asterisk -rx "pjsip show registrations"
    docker compose exec asterisk02 asterisk -rx "pjsip show registrations"
    ```

    ```text
     <Registration/ServerURI..............................>  <Auth....................>  <Status.......>
    ==========================================================================================

     routr/sip:routr:5060                                    routr-auth                  Registered        (exp. 45s)

    Objects found: 1
    ```

    <Check>
    Both servers show `Registered`. If one shows `Rejected`, wait 10 seconds and ask again. If it stays `Rejected`, check that the Peer's username and credentials are `asterisk`/`asterisk`.
    </Check>
  </Step>

  <Step title="Register your softphone">
    Configure the softphone with these values:

    | Setting | Value |
    | --- | --- |
    | Username | `1001` |
    | Password | `1234` |
    | Domain | `sip.local` |
    | Proxy (outbound proxy) | Your machine's IP, for example `192.168.1.3:5060` |
    | Transport | UDP |

    `sip.local` isn't a real DNS name, so the proxy setting tells the softphone where to send requests.

    <Check>
    The softphone shows the account as registered.
    </Check>
  </Step>

  <Step title="Call the Peer and watch Routr balance">
    In a second terminal, open `sngrep` inside the Routr container to watch SIP traffic.

    ```bash
    docker compose exec routr sngrep
    ```

    From the softphone, call `asterisk` (the full URI is `sip:asterisk@sip.local`). Hang up and call again a few times.

    Routr finds the Peer by its username, looks up the routes for `sip:asterisk@sip.local`, and picks the next one in round-robin order. In `sngrep`, the INVITEs that Routr forwards alternate between the two Asterisk container addresses. You also hear "one" on one call and "two" on the next.

    You can also search the Asterisk logs for the message each dialplan writes:

    ```bash
    docker compose logs --no-log-prefix asterisk01 asterisk02 | grep "Call answered by" | grep -v Executing | sort
    ```

    Sorted by time, the output alternates between the two servers, similar to this:

    ```text
    [Oct 26 02:39:06]   Call answered by asterisk01
    [Oct 26 02:39:09]   Call answered by asterisk02
    [Oct 26 02:39:11]   Call answered by asterisk01
    ```

    <Check>
    Consecutive calls land on different Asterisk servers.
    </Check>
  </Step>

  <Step title="Stop one server">
    Stop one Asterisk server and call again.

    ```bash
    docker compose stop asterisk02
    ```

    New calls keep reaching `asterisk01` once the stopped server's registration expires. With `expiration=60` in `pjsip.conf`, that takes up to a minute. Until then, Routr can still pick `asterisk02`, and that call fails. A call that was already in progress on `asterisk02` ends with it; Routr does not move it.

    Start the server again when you're done.

    ```bash
    docker compose start asterisk02
    ```
  </Step>
</Steps>

## Route PSTN calls to the Peer

In production, calls usually arrive from a carrier. To send them to the same pool of Asterisk servers, link a Number to the Peer's AOR. The Number needs a Trunk whose inbound SIP URI matches the host your carrier sends calls to. None of the steps above creates one, so create it first with `rctl trunks create --insecure`. See [Trunks](/reference/resources/trunks) for every field.

If your carrier sends numbers without the leading `+`, turn on `normalizeToE164` on the Trunk so Routr still finds the Number. If it only accepts calls whose From is your number at its domain, turn on `rewriteFromWithNumber` (and set `fromDomain`); for calls from the Peer, Routr takes the Number from the `X-DOD-Number` header. See [Caller identity](/reference/resources/trunks#caller-identity).

```bash
rctl numbers create --insecure
```

```text
This utility will help you create a new Number.
Press ^C at any time to quit.
? Friendly Name (706)604-1487
? Telephony URL tel:+17066041487
? AOR Link sip:asterisk@sip.local
? Trunk My Carrier
? City Columbus, GA
? Select a Country United States
? Session Affinity Header
? Extra Headers
? Ready? Yes
```

When a call for `+17066041487` arrives on the Trunk, Routr finds the Peer whose AOR equals the Number's AOR Link and applies the Peer's balancing algorithm. See [Numbers](/reference/resources/numbers) for every Number field.

## Choose a balancing algorithm

| Algorithm | How Routr picks a server | Notes |
| --- | --- | --- |
| `round-robin` | The next registered contact, in order | The default. |
| `least-sessions` | The contact with the lowest session count | Each server reports its count in an `X-Session-Count` header on its REGISTER. |

Turn on session affinity when related calls must reach the same server, for example everyone joining one conference room. Set `withSessionAffinity` on the Peer and a `sessionAffinityHeader` on the Number (such as `X-Room-Id`). Routr sends calls with the same header value to the same server.

<Note>
Both algorithms work with any Location store, including the in-memory cache that `routr-one` uses. You need Redis only when you run more than one Location Service instance, so they share registrations. See [Scale with Redis](/guides/scale-with-redis).
</Note>

<Note>
FreeSWITCH works the same way. Configure a gateway in FreeSWITCH that registers to Routr with the Peer's username and password. Every FreeSWITCH server that registers with those credentials joins the Peer's AOR, and Routr balances new calls across them.
</Note>

## Clean up

Stop and remove the containers.

```bash
docker compose down
```
