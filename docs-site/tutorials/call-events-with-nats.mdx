## What you'll build

You run Routr and a NATS server with Docker Compose, turn on EdgePort's NATS publisher, and subscribe to the events with the `nats` CLI. When you register two softphones and call between them, you see `routr.endpoint.registered`, `routr.call.started`, and `routr.call.ended` messages arrive.

Call events come from EdgePort, so you can feed them to billing, dashboards, or any service that speaks NATS without touching the SIP path.

RoutrOne 3 has no setting for call events. The standalone EdgePort image, `fonoster/routr-edgeport`, still publishes them, turned on with Routr 2's `NATS_PUBLISHER_*` variables. So this tutorial puts a standalone EdgePort in front of `routr-one`: phones talk to that EdgePort, and it hands every message to RoutrOne's Message Dispatcher over gRPC.

For traces and metrics instead of business events, see [Monitor with OpenTelemetry](/guides/monitor-with-opentelemetry).

## Prerequisites

- Docker with Docker Compose
- The [`nats` CLI](https://github.com/nats-io/natscli)
- Node.js 22 or later, to install `rctl`
- Two SIP softphones
- The IP address of your machine on your local network (for example, `192.168.1.3`)

## Steps

<Steps>
  <Step title="Configure the EdgePort">
    Create a folder for the tutorial and an `edgeport.yaml` file inside it. It is the standalone EdgePort's configuration: the address it advertises, its SIP transports, and where it sends messages, RoutrOne's Dispatcher on port `51901`.

    ```yaml edgeport.yaml
    kind: EdgePort
    apiVersion: v2beta1
    ref: edgeport-01
    spec:
      processor:
        addr: routr:51901
      externalAddrs:
        - "${DOCKER_HOST_ADDRESS}"
      methods: [REGISTER, INVITE, ACK, BYE, CANCEL]
      transport:
        - protocol: udp
          port: 5060
        - protocol: tcp
          port: 5060
    ```
  </Step>

  <Step title="Configure RoutrOne">
    Create a `routr.yaml` file next to it. RoutrOne needs an EdgePort section of its own, but in this setup no phone reaches it: its port isn't published.

    ```yaml routr.yaml
    apiVersion: v3
    kind: Routr
    ref: routr-one
    spec:
      edgeport:
        transport:
          - protocol: udp
            port: 5060
      dispatcher:
        bindAddr: 0.0.0.0:51901
      data:
        backend: postgres
        url: secret://env/DATABASE_URL
        apiKeys:
          - secret://env/ROUTR_API_KEY
    ```

    `spec.dispatcher.bindAddr` is where the standalone EdgePort reaches the Dispatcher. `51901` is the default; the line makes it visible. The Dispatcher authenticates nobody here, and logs a warning saying so. Its port stays inside the Compose network.
  </Step>

  <Step title="Define the services">
    Create a `compose.yaml` file. It runs NATS, PostgreSQL, the job that creates Routr's tables, `routr-one`, and the standalone EdgePort with the NATS publisher turned on.

    Filename: `compose.yaml`

    ```yaml
    services:
      nats:
        image: nats:latest
        ports:
          - 4222:4222

      postgres:
        image: postgres:16-alpine
        environment:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: routr
        healthcheck:
          test: ["CMD", "pg_isready", "-U", "postgres"]
          interval: 2s
          retries: 30

      migrations:
        image: fonoster/routr-pgdata-migrations:2.32.2
        environment:
          DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
        depends_on:
          postgres:
            condition: service_healthy

      routr:
        image: fonoster/routr-one:latest
        environment:
          DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
          ROUTR_API_KEY: ${ROUTR_API_KEY}
        ports:
          - 51907:51907
        volumes:
          - ./routr.yaml:/etc/routr/routr.yaml:ro
        depends_on:
          migrations:
            condition: service_completed_successfully

      edgeport:
        image: fonoster/routr-edgeport:latest
        environment:
          DOCKER_HOST_ADDRESS: ${DOCKER_HOST_ADDRESS}
          NATS_PUBLISHER_ENABLED: "true"
          NATS_PUBLISHER_URL: nats://nats:4222
        ports:
          - 5060:5060
          - 5060:5060/udp
        volumes:
          - ./edgeport.yaml:/etc/routr/edgeport.yaml:ro
        depends_on:
          - nats
          - routr
    ```

    The EdgePort reads three variables for events. They have no key in `edgeport.yaml`:

    | Variable | Purpose | Default |
    | --- | --- | --- |
    | `NATS_PUBLISHER_ENABLED` | Set to `true` to publish events | Off |
    | `NATS_PUBLISHER_URL` | NATS server to connect to | `nats://localhost:4222` |
    | `NATS_PUBLISHER_SUBJECT` | Prefix for every subject | `routr` |

    See [The standalone EdgePort](/reference/environment-variables#the-standalone-edgeport) for the other variables it still reads.
  </Step>

  <Step title="Start the stack">
    Start the services. Replace the address with your own.

    ```bash
    export ROUTR_API_KEY=$(openssl rand -hex 32)
    DOCKER_HOST_ADDRESS=192.168.1.3 docker compose up -d
    ```

    Keep `ROUTR_API_KEY` set in the terminal where you run `rctl`: it reads the key from there.

    Confirm that the EdgePort connected to NATS.

    ```bash
    docker compose logs edgeport | grep "nats publisher"
    ```

    The output includes a line with this message:

    ```text
    nats publisher enabled with subject routr and url nats://nats:4222
    ```

    <Check>
    The log line above appears, and the `edgeport` and `routr` containers stay up.
    </Check>
  </Step>

  <Step title="Subscribe to Routr events">
    Create a `nats` CLI context for the local server and select it.

    ```bash
    nats context add local --server nats://localhost:4222 --description "Routr events" --select
    ```

    Subscribe to every subject under `routr`. Leave this running.

    ```bash
    nats sub "routr.>"
    ```

    ```text
    Subscribing on routr.>
    ```
  </Step>

  <Step title="Create a Domain and two Agents">
    In another terminal, install `rctl`.

    ```bash
    npm install --location=global @routr/ctl
    ```

    Create a Domain with the SIP URI `sip.local`.

    ```bash
    rctl domains create --endpoint localhost:51907 --insecure
    ```

    Create credentials and an Agent for `1001`, then repeat for `1002`. Pick the Domain `sip.local` and the matching credentials when `rctl agents create` asks.

    ```bash
    rctl credentials create --endpoint localhost:51907 --insecure
    rctl agents create --endpoint localhost:51907 --insecure
    ```

    `--endpoint localhost:51907` is the Data API's port. `--insecure` is required because this setup doesn't use TLS on the Data API.
  </Step>

  <Step title="Register the softphones">
    Configure each softphone with one Agent: its username and password, `sip.local` as the domain, and your machine's IP (for example, `192.168.1.3:5060`) as the outbound proxy over UDP.

    Each successful registration publishes an event.

    ```text
    [#1] Received on "routr.endpoint.registered"
    {"aor":"sip:1001@sip.local","registeredAt":"2026-10-21T15:02:11.482Z","expires":600,"extraHeaders":{}}
    ```

    <Check>
    You see one `routr.endpoint.registered` message per softphone. Softphones re-register periodically, so more arrive over time.
    </Check>
  </Step>

  <Step title="Make a call">
    From `1001`, call `1002`. When Routr forwards the INVITE, EdgePort publishes `routr.call.started`.

    ```text
    [#3] Received on "routr.call.started"
    {"callId":"_Ax7XxHju-o7fbemWxxLww..","from":"sip:1001@sip.local","to":"sip:1002@sip.local","startTime":"2026-10-21T15:03:10.111Z","extraHeaders":{}}
    ```

    Hang up. EdgePort publishes `routr.call.ended` with the same `callId`.

    ```text
    [#4] Received on "routr.call.ended"
    {"callId":"_Ax7XxHju-o7fbemWxxLww..","endTime":"2026-10-21T15:03:55.760Z","hangupCause":"NORMAL_CLEARING","extraHeaders":{}}
    ```

    <Frame caption="routr.call.started as shown by nats sub (captured on an earlier release, so the fields differ slightly)">
      <img src="/images/call-events-with-nats/nats-sub-routr-call-started.png" alt="Terminal running nats sub routr.call.started and receiving a JSON event with callId, from, to, and startTime" />
    </Frame>

    <Frame caption="routr.call.ended as shown by nats sub (captured on an earlier release)">
      <img src="/images/call-events-with-nats/nats-sub-routr-call-ended.png" alt="Terminal running nats sub routr.call.ended and receiving a JSON event with callId, endTime, and hangupCause NORMAL_CLEARING" />
    </Frame>

    <Check>
    For one call you see one `routr.call.started` and one `routr.call.ended`, and both carry the same `callId`.
    </Check>
  </Step>
</Steps>

## Event reference

| Subject | Published when | Fields |
| --- | --- | --- |
| `routr.endpoint.registered` | A REGISTER succeeds | `aor`, `registeredAt`, `expires`, `extraHeaders` |
| `routr.call.started` | EdgePort forwards an INVITE | `callId`, `from`, `to`, `startTime`, `extraHeaders`, plus any metadata the processor attached to the route |
| `routr.call.ended` | A BYE or CANCEL completes, an INVITE fails with a status above 300, or a transport error drops the transaction | `callId`, `endTime`, `hangupCause`, `extraHeaders` |

`extraHeaders` holds every header in the message whose name starts with `X-`. On `routr.call.ended` it also carries the `X-` headers of the INVITE that started the call, so a header such as `X-Call-Ref` correlates both events. If the message that ends the call carries a header with the same name, its value wins. For the list of hangup causes, see [`events.go`](https://github.com/fonoster/routr/blob/v3/internal/edgeport/events.go).

To change the prefix, set `NATS_PUBLISHER_SUBJECT` on the `edgeport` service. For example, `NATS_PUBLISHER_SUBJECT=myserver` publishes `myserver.call.started`, `myserver.call.ended`, and `myserver.endpoint.registered`.

<Tip>
To print events to EdgePort's log instead of NATS while you debug, set `CONSOLE_PUBLISHER_ENABLED=true` on the `edgeport` service. The events are logged at debug level, so also set `logLevel: debug` in `edgeport.yaml`.
</Tip>

## Clean up

Stop and remove the containers, and delete the CLI context.

```bash
docker compose down
nats context rm local
```
