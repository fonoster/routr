## What you'll build

You build a web page that registers to Routr over WebSocket and calls an Asterisk server, without creating an Agent in the database. Instead, you sign a JSON Web Token (JWT) whose claims describe the caller. The browser sends the token in an `X-Connect-Token` header, the Connect processor verifies it with your public key, and treats the caller as an **ephemeral agent** for as long as the token is valid.

RTPEngine, driven by the RTPRelay middleware, bridges the browser's WebRTC media to the plain RTP that Asterisk expects.

This is how you let website visitors call your contact center without giving each of them a SIP account.

## Prerequisites

- Docker with Docker Compose
- Node.js 22 or later
- OpenSSL
- A browser with microphone access (Chrome, Firefox, or Safari)
- The IP address of your machine on your local network (for example, `192.168.1.3`)

## Steps

<Steps>
  <Step title="Create a signing key pair">
    Create a folder for the tutorial and a `keys` folder inside it.

    ```bash
    mkdir -p routr-webrtc/keys && cd routr-webrtc
    ```

    Generate an RSA private key. You sign tokens with it, so keep it secret and never ship it to the browser.

    ```bash
    openssl genpkey -algorithm RSA -out keys/private.key -pkeyopt rsa_keygen_bits:4096
    ```

    Derive the public key from it. Routr uses the public key to verify tokens.

    ```bash
    openssl rsa -in keys/private.key -pubout -out keys/public.key
    ```
  </Step>

  <Step title="Define the services">
    Download the English core sounds. The Asterisk image doesn't include prompts, and the dialplan below plays one.

    ```bash
    mkdir sounds
    curl -sL https://downloads.asterisk.org/pub/telephony/sounds/releases/asterisk-core-sounds-en-ulaw-1.6.1.tar.gz | tar -xz -C sounds
    ```

    Create the PJSIP configuration for Asterisk. It registers to Routr as the `asterisk` Peer, which you create later, and accepts the calls Routr sends back. Until the Peer exists, Routr rejects the registration and Asterisk retries every 10 seconds.

    Filename: `pjsip.conf`

    ```ini
    [transport-udp]
    type=transport
    protocol=udp
    bind=0.0.0.0:5060

    [routr]
    type=registration
    transport=transport-udp
    server_uri=sip:routr:5060
    client_uri=sip:asterisk@sip.local
    outbound_auth=routr-auth
    expiration=60
    retry_interval=10
    forbidden_retry_interval=10

    [routr-auth]
    type=auth
    auth_type=userpass
    username=asterisk
    password=asterisk

    [routr]
    type=endpoint
    transport=transport-udp
    context=local-ctx
    disallow=all
    allow=ulaw,alaw

    [routr]
    type=identify
    endpoint=routr
    match=routr
    ```

    Create a dialplan for Asterisk. It answers calls to the `asterisk` extension and plays a short prompt.

    Filename: `extensions.conf`

    ```ini
    [local-ctx]
    exten => asterisk,1,NoOp()
     same => n,Answer()
     same => n,Playback(hello-world)
     same => n,Hangup()
    ```

    Create a `routr.yaml` file. Besides the database and the API key, it turns on the WebSocket transport the browser uses, relays media through RTPEngine, and gives Connect the public key that verifies tokens.

    ```yaml routr.yaml
    apiVersion: v3
    kind: Routr
    ref: routr-one
    spec:
      edgeport:
        externalAddrs:
          - "${DOCKER_HOST_ADDRESS}"
        transport:
          - protocol: udp
            port: 5060
          - protocol: tcp
            port: 5060
          - protocol: ws
            port: 5062
      connect:
        verifierPublicKeyPath: /keys/public.key
      data:
        backend: postgres
        url: secret://env/DATABASE_URL
        apiKeys:
          - secret://env/ROUTR_API_KEY
      rtprelay:
        host: rtpengine
        port: 22222
    ```

    Create a `compose.yaml` file. It runs PostgreSQL, the job that creates Routr's tables, `routr-one` with the public key mounted, an Asterisk server, and RTPEngine.

    Filename: `compose.yaml`

    ```yaml
    services:
      postgres:
        image: postgres:16-alpine
        environment:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: routr
        healthcheck:
          test: ["CMD", "pg_isready", "-U", "postgres"]
          interval: 2s
          retries: 30

      migrations:
        image: fonoster/routr-pgdata-migrations:2.32.2
        environment:
          DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
        depends_on:
          postgres:
            condition: service_healthy

      routr:
        image: fonoster/routr-one:latest
        environment:
          DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
          ROUTR_API_KEY: ${ROUTR_API_KEY}
          DOCKER_HOST_ADDRESS: ${DOCKER_HOST_ADDRESS}
        ports:
          - 51907:51907
          - 5060:5060
          - 5060:5060/udp
          - 5062:5062
        volumes:
          - ./routr.yaml:/etc/routr/routr.yaml:ro
          - ./keys/public.key:/keys/public.key:ro
        depends_on:
          migrations:
            condition: service_completed_successfully

      asterisk:
        image: andrius/asterisk:22.11.0_debian-trixie
        restart: always
        volumes:
          - ./pjsip.conf:/etc/asterisk/pjsip.conf:ro
          - ./extensions.conf:/etc/asterisk/extensions.conf:ro
          - ./sounds:/var/lib/asterisk/sounds/en:ro

      rtpengine:
        image: fonoster/rtpengine:latest
        platform: linux/amd64
        ports:
          - 22222:22222/udp
          - 10000-10100:10000-10100/udp
        environment:
          RTPENGINE_PUBLIC_IP: ${DOCKER_HOST_ADDRESS}
          RTPENGINE_PORT_MIN: 10000
          RTPENGINE_PORT_MAX: 10100
    ```

    What each setting does:

    - `spec.rtprelay` makes `routr-one` run the RTPRelay after Connect and point it at RTPEngine. To change the media profiles, add `spec.rtprelay.profiles`; without it, RTPRelay uses its defaults. See [RTPRelay](/reference/components/rtprelay).
    - `spec.connect.verifierPublicKeyPath` turns on ephemeral agents. The Connect processor reads the key at startup and verifies every `X-Connect-Token` with it. Only RS256 signatures are accepted. To also require the token's issuer or audience, set `verifierIssuer` or `verifierAudience`; see [`spec.connect`](/reference/configuration#spec-connect).
    - Port `5062` is EdgePort's WebSocket (`ws`) listener. The browser connects there.
    - Port `51907` is the Data API, which `rctl` reaches with the key in `ROUTR_API_KEY`.
    - `andrius/asterisk` is a community-maintained build of stock Asterisk 22, published for amd64 and arm64. `fonoster/rtpengine` is built for amd64 only, so on Apple silicon it runs under emulation.
  </Step>

  <Step title="Start the stack">
    Start the services. Replace the address with your own.

    ```bash
    export ROUTR_API_KEY=$(openssl rand -hex 32)
    DOCKER_HOST_ADDRESS=192.168.1.3 docker compose up -d
    ```

    Keep `ROUTR_API_KEY` set in the terminal where you run `rctl`: it reads the key from there.

    Check that `routr`, `asterisk` and `rtpengine` are up, `postgres` is healthy, and `migrations` exited with code `0`.

    ```bash
    docker compose ps
    ```
  </Step>

  <Step title="Create the Domain and the Asterisk Peer">
    Install `rctl`.

    ```bash
    npm install --location=global @routr/ctl
    ```

    Create a Domain with the SIP URI `sip.local`. An ephemeral agent must belong to a Domain that exists.

    ```bash
    rctl domains create --endpoint localhost:51907 --insecure
    ```

    Create credentials with username `asterisk` and password `asterisk`, then a Peer with username `asterisk`, AOR `sip:asterisk@sip.local`, and those credentials.

    ```bash
    rctl credentials create --endpoint localhost:51907 --insecure
    rctl peers create --endpoint localhost:51907 --insecure
    ```

    Within 10 seconds, Asterisk retries and registers. Check its status.

    ```bash
    docker compose exec asterisk asterisk -rx "pjsip show registrations"
    ```

    <Check>
    The `routr/sip:routr:5060` registration shows `Registered`.
    </Check>

    Print the Domain's reference. You need it for the token.

    ```bash
    rctl domains get --endpoint localhost:51907 --insecure --extended
    ```

    ```text
    Ref                                  Name           URI         Egress Policies
    a27e9fb2-a71a-4cf3-9b1d-dccf373f9777 Local Domain   sip.local
    ```
  </Step>

  <Step title="Sign a token">
    Set up a small Node.js project and install `jsonwebtoken`.

    ```bash
    npm init -y
    npm install jsonwebtoken
    ```

    Create a script that signs the claims with your private key. Replace `domainRef` with the reference from the previous step.

    Filename: `create-jwt.js`

    ```javascript
    const fs = require("fs");
    const jwt = require("jsonwebtoken");

    const privateKey = fs.readFileSync("keys/private.key");

    const payload = {
      ref: "agent-visitor-01",
      domainRef: "a27e9fb2-a71a-4cf3-9b1d-dccf373f9777",
      domain: "sip.local",
      aor: "sip:visitor@sip.local",
      aorLink: "sip:asterisk@sip.local",
      allowedMethods: ["INVITE", "REGISTER"]
    };

    const token = jwt.sign(payload, privateKey, {
      algorithm: "RS256",
      expiresIn: "1h"
    });

    console.log(token);
    ```

    The claims tell Routr who the caller is and what they can do:

    | Claim | Meaning |
    | --- | --- |
    | `ref` | An identifier for the ephemeral agent |
    | `domain` | The Domain's SIP URI. It must match an existing Domain. |
    | `domainRef` | The Domain's reference |
    | `aor` | The address the browser registers under. It can be any URI in the Domain. |
    | `aorLink` | The AOR of the Peer that receives the visitor's calls |
    | `allowedMethods` | `REGISTER` lets the client register; `INVITE` lets it place calls |
    | `maxContacts` | Optional. Limits how many registrations the AOR accepts. |

    Run the script and copy the token it prints.

    ```bash
    node create-jwt.js
    ```

    ```text
    eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.eyJyZWYiOiJhZ2VudC12aXNpdG9yLTAxIiwi...
    ```

    <Warning>
    In production, sign tokens on your backend after you decide the visitor may call, and keep `expiresIn` short. Anyone holding a valid token can call the `aorLink` until it expires.
    </Warning>
  </Step>

  <Step title="Build the web client">
    Create a page that uses SIP.js's `SimpleUser` to connect to EdgePort's WebSocket port, register, and call. The token goes in an `X-Connect-Token` header on both the REGISTER and the INVITE. Replace the token and the IP address.

    Filename: `index.html`

    ```html
    <!doctype html>
    <html lang="en">
      <head>
        <meta charset="utf-8" />
        <title>Routr browser call</title>
      </head>
      <body>
        <p id="status">Connecting...</p>
        <button id="call">Call</button>
        <button id="hangup">Hang up</button>
        <audio id="remoteAudio" autoplay></audio>

        <script type="module">
          import { Web } from "https://esm.sh/sip.js@0.21.2";

          const token = "PASTE_YOUR_TOKEN_HERE";
          const server = "ws://192.168.1.3:5062";
          const extraHeaders = [`X-Connect-Token: ${token}`];
          const status = document.getElementById("status");

          const simpleUser = new Web.SimpleUser(server, {
            aor: "sip:visitor@sip.local",
            media: {
              remote: { audio: document.getElementById("remoteAudio") }
            },
            registererOptions: { extraHeaders },
            delegate: {
              onRegistered: () => (status.textContent = "Registered"),
              onCallAnswered: () => (status.textContent = "In call"),
              onCallHangup: () => (status.textContent = "Registered")
            }
          });

          await simpleUser.connect();
          await simpleUser.register();

          document.getElementById("call").onclick = () =>
            simpleUser.call("sip:asterisk@sip.local", { extraHeaders });

          document.getElementById("hangup").onclick = () =>
            simpleUser.hangup();
        </script>
      </body>
    </html>
    ```

    <Note>
    This page loads SIP.js from a CDN to keep the tutorial short. In a real app, install `sip.js` from npm and bundle it.
    </Note>
  </Step>

  <Step title="Serve the page and register">
    Browsers only allow microphone access on `https` pages or on `localhost`. Serve the folder on `localhost`.

    ```bash
    npx serve -l 8080 .
    ```

    Open `http://localhost:8080` and allow microphone access when asked.

    <Check>
    The page shows **Registered**. Routr accepted the REGISTER because the token verified, and it stored the browser's route under `sip:visitor@sip.local`.
    </Check>

    If the page stays on **Connecting...**, check that port `5062` is published and the IP in `server` is correct. If the registration fails with `403 Forbidden`, the token didn't verify: check that `public.key` matches the private key, the token hasn't expired, and `domain` matches your Domain's SIP URI.
  </Step>

  <Step title="Call Asterisk">
    Click **Call**. Routr verifies the token on the INVITE, finds the Peer whose AOR equals `aorLink`, and routes the call `agent-to-peer`. RTPRelay asks RTPEngine to bridge the browser's WebRTC media to Asterisk.

    <Check>
    The page shows **In call** and you hear Asterisk's "Hello world" prompt in the browser.
    </Check>
  </Step>
</Steps>

## Clean up

Stop the static server with `Ctrl+C`, then stop and remove the containers.

```bash
docker compose down
```

## Use a verifier service instead of a key

If you'd rather not mount a public key in Routr, run a gRPC service that implements the `Verifier` interface in [`verifier.proto`](https://github.com/fonoster/routr/blob/v3/protos/verifier.proto) and set `spec.connect.verifierAddr` (for example, `verifier:51915`) instead of `verifierPublicKeyPath`. Set only one of the two; Routr refuses to start with both. `spec.connect.verifierAuth` says how to reach the service; see [client keys](/reference/configuration#client-keys).
