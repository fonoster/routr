title: "Quickstart"
description: "Run Routr on your machine with Docker, create a Domain and two Agents with rctl, and make your first call between two softphones."
---

In this tutorial, you run the all-in-one Routr image and a PostgreSQL database with Docker Compose, create a SIP Domain and two Agents with the `rctl` command-line tool, register two softphones, and call from one to the other.

## What you'll build

A single Routr server on your machine with:

- A Domain named `sip.local`.
- Two Agents, `1001` (John) and `1002` (Jane), each with its own Credentials.
- Two softphones registered to Routr that can call each other.

It takes about ten minutes.

## Prerequisites

- [Docker](https://docs.docker.com/get-docker/) with Docker Compose.
- [Node.js](https://nodejs.org/en/download/) 22 or later and npm, to install `rctl`.
- Two SIP softphones, for example [Zoiper](https://www.zoiper.com/) or Telephone. You can run them on the same computer or on two devices on the same network.
- The IP address of the machine that runs Docker, as seen by your softphones (for example `192.168.1.3`).

## Steps

<Steps>
  <Step title="Write the configuration">
    Create a directory named `routr`. In it, add a file named `routr.yaml` with the following content. It is the one file Routr reads: the SIP transports, and the database where the Data API keeps your resources.

    ```yaml routr.yaml
    apiVersion: v3
    kind: Routr
    ref: routr-one
    spec:
      edgeport:
        externalAddrs:
          - "${DOCKER_HOST_ADDRESS}"
        transport:
          - protocol: udp
            port: 5060
          - protocol: tcp
            port: 5060
      data:
        backend: postgres
        url: secret://env/DATABASE_URL
        apiKeys:
          - secret://env/ROUTR_API_KEY
    ```

    Here's what each part does:

    - `externalAddrs` is the address the EdgePort advertises in SIP messages. `${DOCKER_HOST_ADDRESS}` reads it from the container's environment. Use an address your softphones can reach.
    - `transport` opens SIP on port `5060` over UDP and TCP.
    - `data` stores resources in PostgreSQL. `url` and the API key come from the container's environment, so the file holds no secret.
    - `apiKeys` is required: the Data API returns credentials and takes writes, so it refuses to listen beyond loopback without authentication. `rctl` sends the key with every request.

    See [routr.yaml](/reference/configuration) for every key.
  </Step>

  <Step title="Start Routr">
    In the same directory, add a file named `compose.yaml`. It runs a PostgreSQL database, Routr 2's migrations image, which creates the tables Routr 3 still uses, and `fonoster/routr-one`, which runs the EdgePort, Message Dispatcher, Connect processor, Location Service and Data API in one process.

    ```yaml compose.yaml
    services:
      postgres:
        image: postgres:16-alpine
        environment:
          POSTGRES_USER: postgres
          POSTGRES_PASSWORD: postgres
          POSTGRES_DB: routr
        healthcheck:
          test: ["CMD", "pg_isready", "-U", "postgres"]
          interval: 2s
          retries: 30
        volumes:
          - db:/var/lib/postgresql/data

      migrations:
        image: fonoster/routr-pgdata-migrations:2.32.2
        environment:
          DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
        depends_on:
          postgres:
            condition: service_healthy

      routr:
        image: fonoster/routr-one:latest
        environment:
          DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
          ROUTR_API_KEY: ${ROUTR_API_KEY}
          DOCKER_HOST_ADDRESS: ${DOCKER_HOST_ADDRESS}
        ports:
          - 51907:51907
          - 5060:5060/udp
          - 5060:5060/tcp
        volumes:
          - ./routr.yaml:/etc/routr/routr.yaml:ro
        depends_on:
          migrations:
            condition: service_completed_successfully

    volumes:
      db:
    ```

    Port `51907` is the Data API, which `rctl` talks to. Port `5060` is SIP signaling. The `db` volume keeps the database between restarts.

    Pick an API key and export it, so both the container and `rctl` get it. Then start the stack, replacing `192.168.1.3` with your own IP address.

    ```bash
    export ROUTR_API_KEY=$(openssl rand -hex 32)
    DOCKER_HOST_ADDRESS=192.168.1.3 docker compose up -d
    ```

    Then follow the logs until Routr is up:

    ```bash
    docker compose logs -f routr
    ```

    Look for a line with `msg="starting routr"`. Press `Ctrl+C` to stop following the logs; the server keeps running. If Routr stopped instead, its last line names the key of `routr.yaml` it couldn't use.

    <Check>
      Routr is running and listening for SIP on port `5060` and for API calls on port `51907`.
    </Check>
  </Step>

  <Step title="Install rctl">
    Install the Routr command-line tool globally with npm:

    ```bash
    npm install -g @routr/ctl
    ```

    Check that it's installed:

    ```bash
    rctl --version
    ```

    Every command in this tutorial passes `--insecure`, because this Data API has no TLS, and `--endpoint localhost:51907`, because `rctl` still defaults to Routr 2's port `51908`. `rctl` reads the API key from `ROUTR_API_KEY`, which you exported in the same shell. To add TLS, see [Secure the server](/guides/secure-the-server).
  </Step>

  <Step title="Create a Domain">
    A Domain groups Agents that can call each other. Create one with the SIP URI `sip.local`:

    ```bash
    rctl domains create --insecure --endpoint localhost:51907
    ```

    Answer the prompts as shown. Leave the access control list set to `None`.

    ```text
    This utility will help you create a new Domain.
    Press ^C at any time to quit.
     ›   Warning: Egress rules unavailable due to 0 configured numbers.
    ? Friendly Name Local Domain
    ? SIP URI sip.local
    ? IP Access Control List None
    ? Ready? Yes
    Creating Domain Local Domain... a27e9fb2-a71a-4cf3-9b1d-dccf373f9777
    ```
  </Step>

  <Step title="Create Credentials for both Agents">
    Credentials hold the username and password a softphone uses to register. Create the first set:

    ```bash
    rctl credentials create --insecure --endpoint localhost:51907
    ```

    Use `1001` as the username and `1234` as the password:

    ```text
    This utility will help you create a new set of Credentials.
    Press ^C at any time to quit.
    ? Friendly Name John Doe Credentials
    ? Username 1001
    ? Password [hidden]
    ? Ready? Yes
    Creating Credentials John Doe Credentials... 8814fc24-2328-43af-82d4-f5347fe4521b
    ```

    Run the command again to create `Jane Doe Credentials` with username `1002` and password `1234`.
  </Step>

  <Step title="Create two Agents">
    An Agent is a SIP endpoint, such as a softphone, that belongs to a Domain. Create John:

    ```bash
    rctl agents create --insecure --endpoint localhost:51907
    ```

    Select the `sip.local` Domain and John's Credentials. Leave `Max Contacts` empty for no limit, and keep the other defaults.

    ```text
    This utility will help you create a new Agent.
    Press ^C at any time to quit.
    ? Friendly Name John Doe
    ? Select a Domain sip.local
    ? Username 1001
    ? Credentials Name John Doe Credentials
    ? Max Contacts
    ? Privacy None
    ? Enabled? Yes
    ? Ready? Yes
    Creating Agent John Doe... 8dae9a7d-99b8-4279-88e1-4cf6ed67190a
    ```

    Run the command again to create Jane Doe with username `1002` and `Jane Doe Credentials`.

    List the Agents to confirm both exist:

    ```bash
    rctl agents get --insecure --endpoint localhost:51907
    ```

    The output looks similar to this:

    ```text
    Name     Username Domain    Max Contacts Privacy Enabled
    John Doe 1001     sip.local              None    Yes
    Jane Doe 1002     sip.local              None    Yes
    ```

    An empty `Max Contacts` means no limit. Add `-x` to also show each Agent's reference.

    <Check>
      You have a Domain and two Agents that can register and call each other.
    </Check>
  </Step>

  <Step title="Register the softphones">
    Add an account for `1001` in the first softphone and for `1002` in the second. Use these settings:

    | Setting | Value |
    | --- | --- |
    | Domain | `sip.local` |
    | Username | `1001` (or `1002`) |
    | Password | `1234` |
    | Proxy or registrar | Your Docker host IP, port `5060` (for example `192.168.1.3:5060`) |
    | Transport | UDP |

    `sip.local` doesn't resolve in DNS, so the softphone must send its requests to Routr through the proxy setting. In Telephone, the account looks like this:

    <img
      className="rounded-xl"
      src="/images/quickstart/softphone-account.png"
      alt="Telephone account settings for 1001 with domain sip.local, username 1001, and a password"
    />

    And the proxy settings point at the Docker host:

    <img
      className="rounded-xl"
      src="/images/quickstart/softphone-proxy.png"
      alt="Telephone advanced settings with SIP address 1001@sip.local, registry server 192.168.1.2, and proxy 192.168.1.2 on port 5060"
    />

    <Check>
      Both softphones show the account as registered (or online).
    </Check>
  </Step>

  <Step title="Make a call">
    From John's softphone (`1001`), dial `1002`. Jane's softphone rings. Answer it and talk.

    To watch the SIP messages as the call happens, run `sngrep` on the Docker host. The Routr 3 image doesn't include it.

    <Check>
      You made an agent-to-agent call through Routr.
    </Check>
  </Step>
</Steps>

## Clean up

Stop and remove the containers when you're done. Add `-v` to also delete the database volume.

```bash
docker compose down
```

## Troubleshooting

- **The softphone doesn't register.** Check that `DOCKER_HOST_ADDRESS` is an address the softphone can reach, and that the softphone's proxy setting points at it on port `5060`.
- **Registration works, but calls drop or don't ring after a while on UDP.** NAT devices close idle UDP mappings quickly. Lower the softphone's re-register interval, or use TCP. See [EdgePort cooperation](/concepts/edgeport-cooperation) for why connection-oriented transports are recommended.
- **`rctl` can't connect.** Make sure port `51907` is published and that you pass `--insecure --endpoint localhost:51907`.
- **`rctl` reports `authentication required`.** `ROUTR_API_KEY` in your shell isn't the key the container started with. Export the same value and recreate the container with `docker compose up -d`.
- **The `routr` container exits at startup.** Run `docker compose logs routr`. The last line names the file and the key at fault, such as `spec.data.url: secret://env/DATABASE_URL: environment variable DATABASE_URL is not set`.
