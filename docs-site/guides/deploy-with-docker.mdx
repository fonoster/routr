Run the all-in-one `fonoster/routr-one` image on one host. It runs the EdgePort, Message Dispatcher, Connect processor, Location Service and Data API in one process, configured by one file, `routr.yaml`, and backed by a PostgreSQL database you run next to it.

## Prerequisites

- Docker, and Docker Compose if you use the Compose variant. See [Get Docker](https://docs.docker.com/get-docker/).
- The IP address your SIP clients use to reach the host (for example, `192.168.1.3` on a LAN, or the public IP of a VM).
- A PostgreSQL database, or the one in the Compose file below. Routr 3 runs on Routr 2's schema; the image has no database of its own.
- Node.js, if you want to manage resources with [rctl](/guides/manage-resources-with-rctl).

## Know the ports

The routr-one image listens on the following ports. Publish only the ones you use.

| Port                               | Protocol    | Purpose                                                                                             |
| ---------------------------------- | ----------- | --------------------------------------------------------------------------------------------------- |
| `5060`                             | UDP and TCP | SIP signaling                                                                                       |
| `5061`                             | TCP         | SIP over TLS                                                                                        |
| `5062`                             | TCP         | SIP over WebSocket (WS)                                                                             |
| `5063`                             | TCP         | SIP over secure WebSocket (WSS)                                                                     |
| `51907`                            | TCP         | Data API, used by `rctl` and the SDK                                                                |
| `51901`, `51902`, `51904`, `51909` | TCP         | The Dispatcher, Location, Connect and Requester gRPC services, for components outside the container |
| `8080`                             | TCP         | `GET /healthz`, with [`spec.health`](/reference/configuration#spec-health)                          |

Routr 2's port `51908` is gone: the Data API serves `rctl`, the SDK and the other components on `51907`.

## Run the server

<Steps>
  <Step title="Write routr.yaml">
    RoutrOne reads one file, `/etc/routr/routr.yaml`, and no environment variable on its own. The image ships no default file, so you mount yours. This one opens SIP over UDP and TCP and stores resources in PostgreSQL.

    ```yaml routr.yaml
    apiVersion: v3
    kind: Routr
    ref: routr-one
    spec:
      edgeport:
        externalAddrs:
          - "${DOCKER_HOST_ADDRESS}"
        transport:
          - protocol: udp
            port: 5060
          - protocol: tcp
            port: 5060
      data:
        backend: postgres
        url: secret://env/DATABASE_URL
        apiKeys:
          - secret://env/ROUTR_API_KEY
    ```

    `externalAddrs` is what Routr writes in the `Via`, `Contact` and `Record-Route` headers. Inside a container, Routr can't discover the host's address, so set it for calls to work. To advertise more than one address, list each on its own line.

    `${DOCKER_HOST_ADDRESS}` and the two `secret://env` references read the container's environment, not the host's. Each one stops the container at startup when its variable is unset or empty. See [Values: literals, placeholders and secrets](/reference/configuration#values-literals-placeholders-and-secrets).

    `apiKeys` is required as soon as the Data API listens beyond loopback, as it must to be published. Without it, or `tls.clientCAFile`, or `insecure: true`, Routr refuses to start. See [gRPC listeners and authentication](/reference/configuration#grpc-listeners-and-authentication).

  </Step>
  <Step title="Start the containers">
    <Tabs>
      <Tab title="Docker Compose">
        Add a `compose.yaml` next to `routr.yaml`. It runs PostgreSQL, the migrations image (`fonoster/routr-pgdata-migrations`, Routr 2's schema as it is) to create the tables, and routr-one once the migrations have finished. The `db` volume keeps the data across restarts.

        ```yaml compose.yaml
        services:
          postgres:
            image: postgres:16-alpine
            environment:
              POSTGRES_USER: postgres
              POSTGRES_PASSWORD: postgres
              POSTGRES_DB: routr
            healthcheck:
              test: ["CMD", "pg_isready", "-U", "postgres"]
              interval: 2s
              retries: 30
            volumes:
              - db:/var/lib/postgresql/data

          migrations:
            image: fonoster/routr-pgdata-migrations:latest
            environment:
              DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
            depends_on:
              postgres:
                condition: service_healthy

          routr:
            image: fonoster/routr-one:latest
            environment:
              DATABASE_URL: postgresql://postgres:postgres@postgres:5432/routr?schema=public
              ROUTR_API_KEY: ${ROUTR_API_KEY}
              DOCKER_HOST_ADDRESS: ${DOCKER_HOST_ADDRESS}
            ports:
              - 51907:51907
              - 5060:5060/udp
              - 5060:5060/tcp
            volumes:
              - ./routr.yaml:/etc/routr/routr.yaml:ro
            depends_on:
              migrations:
                condition: service_completed_successfully

        volumes:
          db:
        ```

        Start the stack in the background, replacing the address with your own.

        ```bash
        export ROUTR_API_KEY=$(openssl rand -hex 32)
        DOCKER_HOST_ADDRESS=192.168.1.3 docker compose up -d
        ```
      </Tab>
      <Tab title="docker run">
        With a database you already run, create its tables once with the migrations image, then start routr-one. Replace the URL and the address with your own.

        ```bash
        export DATABASE_URL="postgresql://routr:secret@db.example.com:5432/routr?schema=public"
        export ROUTR_API_KEY=$(openssl rand -hex 32)

        docker run --rm -e DATABASE_URL fonoster/routr-pgdata-migrations:latest

        docker run -d --name routr \
          -p 51907:51907 \
          -p 5060:5060/udp -p 5060:5060/tcp \
          -e DATABASE_URL -e ROUTR_API_KEY \
          -e DOCKER_HOST_ADDRESS=192.168.1.3 \
          -v "$PWD/routr.yaml:/etc/routr/routr.yaml:ro" \
          fonoster/routr-one:latest
        ```
      </Tab>
    </Tabs>

    Replace `latest` with a specific version for anything beyond a quick test. The available tags are listed on [Docker Hub](https://hub.docker.com/r/fonoster/routr-one/tags).

    The image runs as UID `1000` and GID `3000`, so the mounted `routr.yaml` must be readable by that user. Keep secrets out of the file with references, as above, rather than tightening its permissions.

  </Step>
  <Step title="Check the container status">
    Wait a few seconds, then read the container's log.

    ```bash
    docker logs routr 2>&1 | grep "starting routr"
    ```

    <Check>A line with `msg="starting routr"` means the server is ready.</Check>

    If the container exits instead, its last log line names the file and the key it couldn't use, for example `config file /etc/routr/routr.yaml: spec.data.url: is required`.

  </Step>
  <Step title="Create your first resource">
    Install the command-line tool.

    ```bash
    npm install --location=global @routr/ctl
    ```

    Create a SIP Domain. `--insecure` is required because this Data API has no TLS. `rctl` connects to `localhost:51907`, the Data API's port, by default, and reads the API key from `ROUTR_API_KEY`.

    ```bash
    rctl domains create --insecure
    ```

  </Step>
</Steps>

## Configure the container

Every setting lives in `routr.yaml`. [routr.yaml](/reference/configuration) lists every key, and [A complete file](/reference/configuration#a-complete-file) shows them together.

When other services reach Routr by a service name, such as `routr` in a Docker Compose network, list that name in `spec.edgeport.aliases`. Routr then treats a Route header that names it, on the port of one of its listening points, as its own.

```yaml routr.yaml
apiVersion: v3
kind: Routr
ref: routr-one
spec:
  edgeport:
    externalAddrs:
      - 203.0.113.10
    aliases:
      - routr
    transport:
      - protocol: udp
        port: 5060
  data:
    backend: postgres
    url: secret://env/DATABASE_URL
    apiKeys:
      - secret://env/ROUTR_API_KEY
```

A value reaches the file in one of three ways:

- A literal, written in the file.
- `${VAR}` or `${VAR:-default}`, which reads the container's environment. Pass the variable with `environment:` in Compose or `-e` in `docker run`.
- A `secret://` reference: `secret://env/NAME`, `secret://file/<path>` for a file mounted in the container (such as a Docker secret under `/run/secrets`), or `secret://k8s/<secret>#<key>`.

An unknown or misspelled key stops the container and names the key. Routr 2's environment variables, such as `EXTERNAL_ADDRS` or `DATABASE_URL`, do nothing unless the file references them. [Environment variables](/reference/environment-variables) maps each one to its key.

To use the files backend instead of PostgreSQL, set `spec.data.backend: files` and `spec.data.path` to a directory of resource files mounted in the container. That backend is read-only: `rctl` and the SDK can read resources but not change them. See [`spec.data`](/reference/configuration#spec-data).

### Features with no Routr 3 key

These Routr 2 settings of routr-one have no equivalent in Routr 3's RoutrOne:

- `HEPLIFY_OPTIONS`: the image doesn't ship heplify.
- Nothing else: the EdgePort's console and NATS call events are `spec.edgeport.events`, and `STRIP_SESSION_PROGRESS_SDP` is `spec.edgeport.stripSessionProgressSdp`; see [spec.edgeport](/reference/configuration#spec-edgeport).
- The internal database (`START_INTERNAL_DB`): run PostgreSQL next to Routr, as above.
- Log format and transport (`LOGS_FORMAT`, `LOGS_TRANSPORT` and the Fluentd variables): Routr 3 writes text lines to standard output, and sends logs over OTLP when [`telemetry`](/reference/configuration#telemetry) is set.

## Upgrade

Routr 3 runs on Routr 2's schema as it is, and its migrations image applies Routr 2's migrations unchanged. Upgrading within 3.x means replacing the containers with newer images. To come from Routr 2, follow [Upgrade from Routr 2](/guides/upgrade-to-routr-3).

<Steps>
  <Step title="Back up your data">
    Dump the database before an upgrade. Read the [changelog](/changelog) for breaking changes.
  </Step>
  <Step title="Change the image tag">
    Set the new version in `compose.yaml` on both images, for example `fonoster/routr-one:3.0.1` and `fonoster/routr-pgdata-migrations:3.0.1`.
  </Step>
  <Step title="Recreate the container">
    Pull the new image and recreate the service. The database volume is reused.

    ```bash
    docker compose pull
    DOCKER_HOST_ADDRESS=192.168.1.3 docker compose up -d
    ```

    With `docker run`, stop and remove the old container, then run the same command with the new tag.

  </Step>
</Steps>

<Note>
Restarting the container drops its SIP connections. By default routr-one keeps registrations in memory, so clients also have to register again on their next refresh. Dialogs are also kept in memory: a request inside a call that started before the restart, a BYE included, is answered `481`. To keep registrations across restarts, store them in Redis. See [Scale the Location Service with Redis](/guides/scale-with-redis).
</Note>

## Troubleshooting

- **The container exits right after it starts.** Read `docker logs routr`. The last line names the key at fault. `refusing to serve the Data API ... with no authentication` means `spec.data` needs `apiKeys`, `tls.clientCAFile` or `insecure: true`.
- **Calls connect but there is no audio, or replies never arrive.** `spec.edgeport.externalAddrs` is missing or wrong. Set it to the address clients use to reach the host.
- **`rctl` fails with a TLS or connection error.** Make sure port `51907` is published. Add `--insecure` when `spec.data` has no `tls`, or `--cacert` when it has.
- **`rctl` reports `authentication required`.** Its `ROUTR_API_KEY`, or `--api-key`, isn't one of `spec.data.apiKeys`.
- **The Data API refuses to start with `spec.data.encryptionKey: is empty, but the database holds encrypted passwords`.** The database came from Routr 2 with `CLOAK_ENCRYPTION_KEY`. Set `spec.data.encryptionKey` to that key.
- **Data disappears after `docker compose down`.** Don't run `docker compose down -v`, which deletes volumes.
- **Only UDP works.** Publish `5060:5060` for TCP, and add a transport and a port for TLS, WS or WSS.
