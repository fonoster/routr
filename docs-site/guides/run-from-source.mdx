Build Routr from a clone of the repository, start its services on your machine with live reload, and run the tests.

## Prerequisites

- **Node.js 22** (CI uses `22.x`). [nvm](https://github.com/nvm-sh/nvm) makes switching versions easy.
- **JDK 17**, with `JAVA_HOME` set. EdgePort and Requester are Java services. CI pins 17 because the Java tests fail on JDK 21.
- **Docker** with Compose, for the optional dependencies (PostgreSQL, Redis, RTPEngine).
- **OpenSSL**, to create the development TLS keystore.
- Optional: [sngrep](https://github.com/irontec/sngrep) to watch SIP traffic and [grpcurl](https://github.com/fullstorydev/grpcurl) to call the gRPC services.

<Tip>
  The recommended path is to [develop with dev containers](/guides/develop-with-dev-containers): you get the same toolchain without installing it, and the hostnames and TLS keystore are set up for you.
</Tip>

## Build and start

<Steps>
  <Step title="Clone and build">
    Clone the repository, point `JAVA_HOME` at your JDK, and build everything. `npm run make` installs dependencies, builds the Node.js workspaces, and builds the Java services with Gradle:

    ```bash
    git clone https://github.com/fonoster/routr
    cd routr
    export JAVA_HOME=/path/to/jdk-17
    npm run make
    ```
  </Step>

  <Step title="Map the service hostnames">
    The development configs in `config/` address services by name (`dispatcher:51901`, `location:51902`, `connect:51904`, `apiserver:51907`). Append the entries in `etc/hosts.txt`, which map each name to `127.0.0.1`, to `/etc/hosts`:

    ```bash
    sudo sh -c 'cat etc/hosts.txt >> /etc/hosts'
    ```

    Run it once. To undo it, delete those lines from `/etc/hosts`.
  </Step>

  <Step title="Create the TLS keystore">
    `config/edgeport.yaml` enables TLS and WSS and reads its keystore from `/etc/routr/certs/signaling.p12` with the password `changeme`. Generate a self-signed keystore and copy it there:

    ```bash
    npm run generate:certs
    ./.scripts/convert-to-p12.sh .certs
    sudo mkdir -p /etc/routr/certs
    sudo cp .certs/signaling.p12 /etc/routr/certs/signaling.p12
    ```
  </Step>

  <Step title="Check the setup">
    Run the smoke test. It starts an EdgePort, the Message Dispatcher, and the Echo processor (on the Connect processor's port, `51904`), sends a SIP `MESSAGE` over UDP to `127.0.0.1:5060`, and needs no database:

    ```bash
    npm run test:echo
    ```

    <Check>
      The test prints `echo test passed: SIP/2.0 200 OK` and exits with code `0`. It exits with code `1` on any other answer, or when nothing answers within 120 seconds.
    </Check>
  </Step>

  <Step title="Start the services">
    Start the Connect distribution in one process:

    ```bash
    npm start
    ```

    This runs two EdgePorts (`config/edgeport.yaml` on port `5060`, `config/edgeport.alt.yaml` on port `6060`), the Message Dispatcher, Location Service, Registry, Requester, the Connect processor, and the API Server with the YAML backend (`simpledata`, reading `config/resources`). Nodemon restarts the Node.js services when you edit their source. EdgePort and Requester are Java: rebuild them with `npm run build:java` and restart.

    <Check>
      The log shows `routr v2 // connect distribution` followed by a `starting routr service` line for each Node.js service.
    </Check>
  </Step>
</Steps>

Register a softphone against `sip.local` on port `5060` with one of the Agents in `config/resources/agents.yaml` to try it.

## Run a single service

Each component has its own script, so you can run only what you work on, each in its own terminal. For example, to work on the Location Service with an EdgePort:

```bash
npm run start:edgeport
npm run start:location
```

| Script | Starts | Config |
| --- | --- | --- |
| `start:edgeport` | EdgePort (Java) | `config/edgeport.yaml` |
| `start:dispatcher` | Message Dispatcher | `config/dispatcher.yaml` |
| `start:location` | Location Service | `config/location.yaml` |
| `start:registry` | Registry | `config/registry.yaml` |
| `start:requester` | Requester (Java) | |
| `start:connect` | Connect processor | `API_ADDR=localhost:51907`, `LOCATION_ADDR=localhost:51902` |
| `start:simpledata` | API Server, YAML backend | `config/resources` |
| `start:pgdata` | API Server, PostgreSQL backend | needs `DATABASE_URL` |
| `start:simpleauth` | SimpleAuth middleware | `config/auth.yaml`, `METHODS=MESSAGE` |
| `start:rtprelay` | RTPRelay middleware | needs RTPEngine |
| `start:echo` | Echo processor (answers `200 OK` to everything) | |
| `start:one` | All-in-one distribution with `pgdata` | starts PostgreSQL itself, see below |
| `test:echo` | Smoke test: EdgePort, Dispatcher, and Echo answer a SIP `MESSAGE` | |

See the `scripts` section of [`package.json`](https://github.com/fonoster/routr/blob/main/package.json) for the full list.

## Start the dependencies

PostgreSQL, Redis, and RTPEngine only matter when you use `pgdata`, the Redis cache, or RTPRelay. `npm start` and `npm run test:echo` need none of them.

### Let `start:one` start them

The all-in-one distribution starts its own dependencies with Docker Compose, applies the database migrations, and then starts Routr:

```bash
npm run start:one
```

It always starts PostgreSQL. It also starts Redis when `LOCATION_CACHE_PROVIDER` is `redis`, and RTPEngine when `RTPENGINE_HOST` is set. The services publish their ports on `localhost` (see the table below), which is where Routr looks by default: `DATABASE_URL` defaults to `postgresql://postgres:postgres@localhost:5432/routr?schema=public` and `LOCATION_CACHE_PARAMETERS` to `host=localhost,port=6379`. To also keep registrations in Redis and relay media through RTPEngine, run:

```bash
LOCATION_CACHE_PROVIDER=redis RTPENGINE_HOST=localhost npm run start:one
```

<Check>
  The log shows `routr v2 // all in one distribution`.
</Check>

### Start them by hand

For the other scripts, such as `start:pgdata`, start the services yourself. With no arguments, the command starts PostgreSQL and Redis and waits until they're healthy:

```bash
npm run start:deps
```

Name the services to start only some of them:

```bash
npm run start:deps -- postgres rtpengine
```

The services run in the Compose project `routr-deps` and publish their ports on `localhost`:

| Service | Port | Override |
| --- | --- | --- |
| PostgreSQL (user and password `postgres`, database `routr`) | `5432` | `POSTGRES_PORT` |
| Redis | `6379` | `REDIS_PORT` |
| RTPEngine | `22222/udp`, media `10000-10020/udp` | |

If you change `POSTGRES_PORT`, set `DATABASE_URL` to match. Before you start `start:pgdata`, apply the database migrations:

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/routr?schema=public" npm run db:migrate
```

Stop all three services with `npm run stop:deps`. Adminer is no longer part of the setup; connect to PostgreSQL with any client, for example `psql postgresql://postgres:postgres@localhost:5432/routr`.

<Note>
  RTPEngine advertises `DOCKER_HOST_ADDRESS` as its media address, `127.0.0.1` when unset. Set it to an IP your SIP clients can reach before the service starts. Compose can't use host networking on macOS, so the media ports are published instead.
</Note>

## Run the tests

Run the same checks as CI before you open a pull request:

```bash
npm test             # Node.js unit tests (mods/*/test/*.unit.test.ts)
npm run test:java    # EdgePort and Requester tests (JDK 17)
npm run typecheck
npx eslint mods --ext .ts
npm run test:echo    # smoke test, no database needed
```

`npm test` runs against the built workspaces, so run `npm run make` (or `npx lerna run build`) after pulling. `npm run lint` also lints, but it applies `--fix` and rewrites files.

To run the SIP Connect compliance scenarios (SEET) against containers built from your tree:

```bash
docker compose -f compose.yaml -f compose.dev.yaml up \
  --build --abort-on-container-exit --exit-code-from compliance compliance
```

## Pitfalls

- **`Could not find a runtime environment`**: `JAVA_HOME` isn't set in the shell that runs the script.
- **Connection errors to `location` or `apiserver`**: the hostnames aren't mapped. Append `etc/hosts.txt` to `/etc/hosts` (see [Map the service hostnames](#build-and-start)).
- **Build errors in `@routr/ctl` after `npm install`**: use `npm ci` so the dependency tree matches `package-lock.json`.
- **Start fresh**: `npm run clean` removes `node_modules`, `dist`, and Gradle outputs.
