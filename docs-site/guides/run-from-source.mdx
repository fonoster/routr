Build Routr from a clone of the repository, start its services on your machine with live reload, and run the tests.

## Prerequisites

- **Go 1.26** or later. Every Routr component is Go: `cmd/<name>` holds each binary, `internal/` the code.
- **Node.js 22** (CI uses `22.x`), for `rctl`, the SDK, the example processors and the scripts. [nvm](https://github.com/nvm-sh/nvm) makes switching versions easy.
- **Docker** with Compose, for the optional dependencies (PostgreSQL, Redis, RTPEngine) and the compliance suite.
- **OpenSSL**, to create the development TLS keystore.
- Optional: [sngrep](https://github.com/irontec/sngrep) to watch SIP traffic and [grpcurl](https://github.com/fullstorydev/grpcurl) to call the gRPC services.

<Tip>
  The recommended path is to [develop with dev containers](/guides/develop-with-dev-containers): you get the same toolchain without installing it, and the hostnames and TLS keystore are set up for you.
</Tip>

## Build and start

<Steps>
  <Step title="Clone and build">
    Clone the repository, install the Node.js workspaces with `npm ci` (not `npm install`, which drifts a pinned dependency), and build them. The Go components build when you run them.

    ```bash
    git clone https://github.com/fonoster/routr
    cd routr
    npm ci
    npx lerna run build
    ```

  </Step>

  <Step title="Map the service hostnames">
    The development files in `config/` address components by name (`dispatcher:51901`, `location:51902`, `connect:51904`, `apiserver:51907`, `requester:51909`). Append the entries in `etc/hosts.txt`, which map each name to `127.0.0.1`, to `/etc/hosts`:

    ```bash
    sudo sh -c 'cat etc/hosts.txt >> /etc/hosts'
    ```

    Run it once. To undo it, delete those lines from `/etc/hosts`.

  </Step>

  <Step title="Create the TLS keystore">
    `config/edgeport.yaml` enables TLS and WSS and reads its keystore from `/etc/routr/certs/signaling.p12` with the password `changeme`. Generate a self-signed keystore and copy it there:

    ```bash
    npm run generate:certs
    ./.scripts/convert-to-p12.sh .certs
    sudo mkdir -p /etc/routr/certs
    sudo cp .certs/signaling.p12 /etc/routr/certs/signaling.p12
    ```

  </Step>

  <Step title="Check the setup">
    Run the smoke test. It starts an EdgePort, the Message Dispatcher, and the Echo processor (on the Connect processor's port, `51904`), sends a SIP `MESSAGE` over UDP to `127.0.0.1:5060`, and needs no database:

    ```bash
    npm run test:echo
    ```

    <Check>
      The test prints `echo test passed: SIP/2.0 200 OK` and exits with code `0`. It exits with code `1` on any other answer, or when nothing answers within 120 seconds.
    </Check>

  </Step>

  <Step title="Start the services">
    Start every component, one process each:

    ```bash
    npm start
    ```

    This runs `go run ./cmd/<name>` for the Data API (`config/data.yaml`, files backend reading `config/resources`), the Location Service, the Connect processor, the Message Dispatcher, the Requester, the Registry, and two EdgePorts (`config/edgeport.yaml` on port `5060`, `config/edgeport.alt.yaml` on port `6060`). Each reads the file in `config/` that `CONFIG_PATH` names. Stop it with `Ctrl+C` and start it again after you edit Go code.

  </Step>
</Steps>

Register a softphone against `sip.local` on port `5060` with one of the Agents in `config/resources/agents.yaml` to try it.

## Run a single component

Each component has its own script, so you can run only what you work on, each in its own terminal. For example, to work on the Location Service with an EdgePort:

```bash
npm run start:edgeport
npm run start:location
```

| Script             | Starts                                                            | Config                                              |
| ------------------ | ----------------------------------------------------------------- | --------------------------------------------------- |
| `start:edgeport`   | EdgePort                                                          | `config/edgeport.yaml`                              |
| `start:dispatcher` | Message Dispatcher                                                | `config/dispatcher.yaml`                            |
| `start:location`   | Location Service                                                  | `config/location.yaml`                              |
| `start:registry`   | Registry                                                          | `config/registry.yaml`                              |
| `start:requester`  | Requester                                                         | `config/requester.yaml`                             |
| `start:connect`    | Connect processor                                                 | `config/connect.yaml`                               |
| `start:data`       | Data API, files backend                                           | `config/data.yaml`, resources in `config/resources` |
| `start:rtprelay`   | RTPRelay                                                          | `config/rtprelay.yaml`; needs RTPEngine             |
| `start:one`        | RoutrOne: every component in one process                          | `config/routr.yaml`                                 |
| `start:simpleauth` | SimpleAuth middleware (Node.js example)                           | `config/auth.yaml`, `METHODS=MESSAGE`               |
| `start:echo`       | Echo processor (Node.js example; answers `200 OK` to everything)  |                                                     |
| `test:echo`        | Smoke test: EdgePort, Dispatcher, and Echo answer a SIP `MESSAGE` |                                                     |

Each Go script is `CONFIG_PATH=<file> go run ./cmd/<name>`. To run a component against a file of your own, set `CONFIG_PATH` the same way. See [Standalone component files](/reference/configuration-files) and [routr.yaml](/reference/configuration) for the keys, and the `scripts` section of [`package.json`](https://github.com/fonoster/routr/blob/main/package.json) for the full list.

`config/routr.yaml` is written for the compose network of the compliance suite (`sipHost: 10.111.221.2`, an EdgePort keystore under `/etc/routr/certs`). Before `npm run start:one` on your machine, change those addresses to your own, or remove `spec.registry` and `spec.requester`.

## Start the dependencies

PostgreSQL, Redis, and RTPEngine only matter when you use the Postgres backend, the Redis cache, or RTPRelay. `npm start` and `npm run test:echo` need none of them. With no arguments, this command starts PostgreSQL and Redis and waits until they're healthy:

```bash
npm run start:deps
```

Name the services to start only some of them:

```bash
npm run start:deps -- postgres rtpengine
```

The services run in the Compose project `routr-deps` and publish their ports on `localhost`:

| Service                                                     | Port                                 | Override        |
| ----------------------------------------------------------- | ------------------------------------ | --------------- |
| PostgreSQL (user and password `postgres`, database `routr`) | `5432`                               | `POSTGRES_PORT` |
| Redis                                                       | `6379`                               | `REDIS_PORT`    |
| RTPEngine                                                   | `22222/udp`, media `10000-10020/udp` |                 |

Routr 3 runs on Routr 2's schema plus three numbering migrations; its migrations are in `ops/pgdata-migrations`. Build the migrations image from the checkout and create the tables with it:

```bash
docker build -f ops/pgdata-migrations/Dockerfile -t routr-pgdata-migrations .
docker run --rm --network routr-deps_default \
  -e DATABASE_URL="postgresql://postgres:postgres@postgres:5432/routr?schema=public" \
  routr-pgdata-migrations
```

Then point the Data API at the database: set `spec.data.backend: postgres` and `spec.data.url` in its file, for example `url: ${DATABASE_URL}`. Point the Location at Redis with `spec.cache.provider: redis` and `parameters: host=localhost,port=6379`.

The services keep running until you stop them. Stop all three with `npm run stop:deps`. Connect to PostgreSQL with any client, for example `psql postgresql://postgres:postgres@localhost:5432/routr`.

<Note>
  RTPEngine advertises `DOCKER_HOST_ADDRESS` as its media address (Compose passes it to the image as `RTPENGINE_PUBLIC_IP`), `127.0.0.1` when unset. Set it to an IP your SIP clients can reach before the service starts. Compose can't use host networking on macOS, so the media ports are published instead. The `fonoster/rtpengine` image is amd64 only, so on Apple silicon it runs under emulation.
</Note>

## Run the tests

Run the same checks as CI before you open a pull request:

```bash
test -z "$(gofmt -l .)" && go vet ./... && go test -race ./...
npm test             # Node.js unit tests (mods/*/test/*.unit.test.ts)
npm run typecheck
npx eslint mods --ext .ts
npm run compat -- --sip-connect   # replays the known-good corpus through the Go chain
npm run test:echo    # smoke test, no database needed
```

`npm test` runs against the built workspaces, so run `npx lerna run build` after pulling. `npm run lint` also lints, but it applies `--fix` and rewrites files.

The Postgres store tests run against a real database when `TEST_DATABASE_URL` names one with Routr 2's tables, as in CI; without it they are skipped.

To run the SIP Connect compliance scenarios (SEET) against containers built from your tree, first create the certificates the EdgePort and the fake carrier share, then run the suite:

```bash
sh .scripts/dev-certs.sh
docker compose -f compose.yaml -f compose.dev.yaml up --build -d
docker compose -f compose.yaml -f compose.dev.yaml up \
  --abort-on-container-exit --exit-code-from compliance compliance
```

The certificates land in `etc/certs`, which git ignores. The EdgePort builds its keystore from them and the fake carrier serves the same certificate on its TLS port, which is how the scenario that calls a provider over TLS is trusted.

Every service in `compose.dev.yaml` sends its traces, metrics, and logs to the `otel-lgtm` service (`grafana/otel-lgtm`). To look at them, start it before the suite and open Grafana at `http://localhost:3000` (user and password `admin`):

```bash
docker compose -f compose.yaml -f compose.dev.yaml up -d otel-lgtm
```

If the suite stopped it on exit, `docker start otel-lgtm` brings it back with its data. See [Monitor with OpenTelemetry](/guides/monitor-with-opentelemetry) for what Routr exports.

## Pitfalls

- **A component exits at startup**: its last line names the file and the key at fault, for example `config file .../config/connect.yaml: spec.apiAddr: is required`.
- **Connection errors to `location` or `apiserver`**: the hostnames aren't mapped. Append `etc/hosts.txt` to `/etc/hosts` (see [Map the service hostnames](#build-and-start)).
- **Build errors in `@routr/ctl` after `npm install`**: use `npm ci` so the dependency tree matches `package-lock.json`.
- **Start fresh**: `npm run clean` removes `node_modules` and `dist`.
