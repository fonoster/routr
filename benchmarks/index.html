01 · CAPACITY

EdgePort + Echo

Not run

This benchmark was not part of this run. Last result: Passed on Nov 4, 2026 (v2.32.1). View that run

What it measures

The EdgePort on its own, with Echo answering every request with 200 OK. No Dispatcher, Connect or database, so this is a ceiling for EdgePort alone, not for a full deployment.

Why it matters

The EdgePort is the only stateful piece of Routr. When it saturates, calls fail, no matter what runs behind it.

How it runs

SIPp sends SIP MESSAGE requests over UDP, starting at 25 messages/s and adding 25 every minute, after a 30-second warm-up that is not measured. The run stops at the first step where p99 MESSAGE-to-200 latency reaches 50 ms or failed requests reach 0.1%.

02 · SOAK

RoutrOne, six hours

Passed

6 h + 30 min warm-up · steady 1 calls/s, 30 s calls, 200 agents

SIPp 3.7.3, UDP; OpenTelemetry

What it measures

The whole stack in one image, EdgePort plus Dispatcher, Connect, Location and the data service in one Node process, routing calls between registered agents.

Why it matters

Leaks only show after hours. A short test can pass while memory climbs until the process is killed in production.

How it runs

SIPp holds a steady 1 call/s for six hours, with 200 registered callee agents, each called by its own caller agent through Connect. After a 30-minute warm-up, each process's memory may grow at most 5 MB/h.
